Pedago Math login system

A Flutter login screen that signs registered users in with Firebase Authentication, validates input before it reaches the server, and remembers an email address without ever storing the password.

Registered users enter their email address and password. Firebase Authentication verifies the credentials and reports authentication errors back to the screen. The form on the right applies the same validation rules as the app, so you can try them yourself.

Login screen

The screen lives in lib/screens/login_screen.dart and uses Flutter's Form and TextFormField widgets to collect and validate input.

  • Email input field
  • Password input field
  • Password visibility toggle
  • Remember Me checkbox
  • Forgot Password option
  • Login button
  • Registration navigation link

Input validation

Credentials are checked before any authentication attempt. If a check fails, the app shows a message and does not call Firebase.

FieldRule
EmailMust not be empty, and must follow the expected email address format.
PasswordMust not be empty, and must contain at least eight characters.

These checks only validate format. Firebase Authentication decides whether the credentials belong to a valid account.

Firebase Authentication

Sign-in uses Firebase Authentication's signInWithEmailAndPassword(). Select a stage to see what happens.

Remember Me

The app uses the shared_preferences package. When the option is on, the preference and the email address are saved locally and the email is restored the next time the screen opens. When it is off, the saved email is removed and the preference is reset.

Preferenceoff
Saved emailnone
Passwordnever saved

Linked to the demo at the top. Turn it on, enter a valid email and password, then press Log in to see the email saved. The password is never written.

Error handling

Authentication failures are handled with exception handling, and the user gets feedback when credentials are incorrect or something goes wrong. The login screen covers these Firebase cases:

  • Invalid credentials
  • Invalid email address
  • Disabled account
  • Too many login attempts

After any asynchronous call, the screen checks that it is still active before updating the interface, which avoids updating a screen that has already closed.
